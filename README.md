# 🎮 Steam Gift Bot — Telegram-бот выдачи общих Steam-аккаунтов

Полностью готовый бот: раздача общих Steam-аккаунтов (1 бесплатная выдача на пользователя), промокоды на дополнительные выдачи, обязательная подписка на каналы, донаты через Telegram Stars, реклама и полноценная админ-панель.

**Главное правило проекта:** пользователь по умолчанию получает бесплатный аккаунт только **1 раз**, а Steam-аккаунты — **общие**: они никогда не удаляются и не помечаются как использованные после выдачи и могут выдаваться повторно любым пользователям.

## Стек

- Python 3.12+, aiogram 3.x (async)
- SQLAlchemy 2.x (async) + Alembic
- PostgreSQL (продакшен) / SQLite (локальный тест)
- Docker / Docker Compose

## Быстрый старт (локально, SQLite)

```bash
cd steam-gift-bot
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/Mac:
source .venv/bin/activate

pip install -r requirements.txt

# 1. Скопируйте настройки
cp .env.example .env        # Windows: copy .env.example .env

# 2. Отредактируйте .env: впишите BOT_TOKEN и свой Telegram ID в ADMIN_IDS

# 3. Запустите (SQLite: таблицы создадутся автоматически)
python main.py
```

Для PostgreSQL запустите миграции перед первым стартом:

```bash
alembic upgrade head
```

## Запуск через Docker Compose (продакшен, 24/7)

1. Скопируйте `.env.example` в `.env`, укажите `BOT_TOKEN`, `ADMIN_IDS` и пароль PostgreSQL (`POSTGRES_PASSWORD`).
2. Запуск:

```bash
docker compose up -d --build
```

Compose поднимет PostgreSQL + бота, применит миграции (`alembic upgrade head`) и перезапустит бота при сбоях (`restart: unless-stopped`).

Логи: `docker compose logs -f bot`. Остановка: `docker compose down`.

## Бесплатный хостинг 24/7: Neon (БД) + Hugging Face Spaces (запуск)

Без карты и оплаты. Neon — только база данных; сам бот запускается в Hugging Face Space (Docker).

### Шаг 1. База на Neon

1. Зарегистрируйтесь на [neon.tech](https://neon.tech) (Google/GitHub — карта не нужна) → **Create project**.
2. Скопируйте connection string вида:
   `postgresql://neondb_owner:ПАРОЛЬ@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`
3. Приведите его к формату SQLAlchemy (два изменения: `+asyncpg` и `ssl=require`):
   `postgresql+asyncpg://neondb_owner:ПАРОЛЬ@ep-xxxx.eu-central-1.aws.neon.tech/neondb?ssl=require`
   Если пароль содержит спецсимволы (`@`, `#`, `/`) — замените их URL-кодировкой (`@` → `%40` и т.д.).

### Шаг 2. Space на Hugging Face

1. Зарегистрируйтесь на [huggingface.co](https://huggingface.co) → **New → Space** → имя, лицензия, SDK: **Docker**.
2. Загрузите файлы проекта (через веб-интерфейс или git push). README.md уже содержит нужную шапку `sdk: docker, app_port: 7860`.
3. В настройках Space (**Settings → Variables and secrets**) добавьте:
   - Secrets: `BOT_TOKEN`, `ADMIN_IDS`, `DATABASE_URL` (строка из шага 1), `KASPI_NUMBER`, `DISPLAY_TZ`;
   - Variables: `HEALTH_PORT=7860`, `LOG_LEVEL=INFO`.
4. Space соберёт образ и запустит контейнер: `alembic upgrade head` создаст таблицы на Neon, затем бот начнёт polling.
5. **Защита от «сна»**: бесплатный Space засыпает после 48 ч без HTTP-запросов. Добавьте в [cron-job.org](https://cron-job.org) (бесплатно, без карты) GET-запрос к адресу Space каждые 20–30 минут.

⚠️ **Важно про Neon:** не храните данные в SQLite на бесплатных площадках — диск эфемерный, при перезапуске Space база стирается. Всегда используйте `DATABASE_URL` на Neon.

⚠️ **Важно про приватность:** бесплатные Space — публичные (код виден всем). Это безопасно: токен и секреты лежат в Secrets, а не в коде. Если код публиковать нельзя — хостите на своём ПК/VPS с той же базой Neon.

### Запуск со своего ПК с базой на Neon

```bash
# в .env укажите DATABASE_URL из шага 1
alembic upgrade head   # однократно создать таблицы на Neon
python main.py         # бот работает локально, данные живут на Neon
```

## Установка администратора

Администраторы задаются в `.env` через запятую:

```
ADMIN_IDS=123456789,987654321
```

Свой Telegram ID можно узнать у [@userinfobot](https://t.me/userinfobot). После изменения `.env` перезапустите бота. Панель открывается командой `/admin` — доступна только администраторам, остальные получают «⛔ У вас нет доступа».

## Каналы обязательной подписки

1. Добавьте бота **администратором** в каждый канал (без этого Telegram не даст боту проверять подписку).
2. `/admin` → 📢 Каналы → ➕ Добавить канал → отправьте `@username` или ID канала (вид `-100…`) → отправьте ссылку для кнопки (или `-` для публичных каналов).
3. 🔄 Проверить настройки — покажет, может ли бот проверять каждый канал.

Отключённые каналы (🚫) не участвуют в проверке подписки.

## Добавление Steam-аккаунтов

Вручную: `/admin` → 🎮 Steam-аккаунты → ➕ Добавить аккаунт → бот последовательно спросит логин, пароль и игры (через запятую).

Массово: → 📥 Массовая загрузка → отправьте `.txt` файл, по аккаунту в строке:

```
login:password
login:password | Game 1, Game 2, Game 3
```

Каждый аккаунт сохраняется отдельной записью; повторяющиеся пары `логин:пароль` (регистр логина не важен) и битые строки пропускаются с отчётом. Один логин с разными паролями добавляется как отдельный аккаунт.

> Выдача **никогда** не удаляет и не меняет статус аккаунта — только администратор может удалить его вручную (🗑 Удалить аккаунт). История выдач сохраняется даже после удаления аккаунта.

## Промокоды

`/admin` → 🎟 Промокоды → Создать промокод:

1. Код (или «gen» для автогенерации);
2. Сколько дополнительных выдач даёт (например, `5`);
3. Лимит активаций (0 — без лимита);
4. Срок действия в днях (0 — бессрочно).

После активации пользователем: `extra_claims += N`. Каждая выдача по этому праву списывает 1 (`extra_claims_used += 1`). Один и тот же промокод пользователь может активировать только один раз (таблица `promo_uses`); при исчерпании лимита промокод автоматически перестаёт работать.

## Пожертвования (Telegram Stars)

Меню 💰 Пожертвований показывает номер Kaspi обычным текстом (настраивается в `.env`: `KASPI_NUMBER`) и кнопки Stars (суммы настраиваются в ⚙️ Настройках админки). Оплата — официальный Telegram Stars (`send_invoice` с валютой `XTR`, платёжный провайдер не нужен). Каждый платёж пишется в таблицу `payments` (Telegram ID, username, количество Stars, charge_id, дата/время).

Возврат Stars администратором: `/refund <telegram_payment_charge_id>` (charge_id виден в разделе 💰 Пожертвования).

## Реклама

`/admin` → 📢 Реклама → Создать блок: текст → текст кнопки (`-` — без кнопки) → ссылка. Активные блоки показываются в главном меню и после выдачи аккаунта (случайный активный блок, блоков может быть несколько).

## Резервное копирование

```bash
python scripts/backup.py     # SQLite: копия файла; PostgreSQL: pg_dump в backups/
```

Cron-пример (ежедневно в 04:00): `0 4 * * * cd /opt/steam-gift-bot && .venv/bin/python scripts/backup.py`

## Проверка логики (selftest)

```bash
python scripts/selftest.py
```

Проверяет на временной SQLite-базе: бесплатная выдача 1 раз, отказ при повторе, сохранность аккаунтов, промокоды (регистр, лимит, повторная активация), конкурентное списание прав (двойного списания нет), отсутствие списания при пустой базе, массовую загрузку и сброс выдач.

## Логика выдачи (шаги)

1. `/start` → главное меню (⚠️ предупреждение + кнопки).
2. 🎮 Получить аккаунт → проверка наличия аккаунтов → проверка подписки на все активные каналы (кнопки «Подписаться» + «✅ Проверить подписку») → проверка права пользователя.
3. Случайный аккаунт из базы (`ORDER BY random()`), отправка логина/пароля/игр в удобном для копирования виде, запись в `issue_history`, счётчики аккаунта увеличиваются.
4. Аккаунт остаётся в базе и может быть выдан снова.

Права пользователя: `free_claim_used` (бесплатная выдача) либо `extra_claims` (промокоды/админ). Списание — атомарный условный `UPDATE`: при параллельных запросах списывается ровно столько прав, сколько есть, без двойных списаний и порчи данных.

## Безопасность и надёжность

- Токен и секреты — только в `.env` (в код не зашиты), `.env` в `.gitignore` и `.dockerignore`.
- `/admin` защищён фильтром по `ADMIN_IDS`.
- Антифлуд-middleware, глобальный обработчик ошибок, логи в `logs/bot.log` (ротация) и консоль.
- SQLite: WAL + busy_timeout; PostgreSQL: пул соединений + pre_ping.
- Все действия (выдачи, промокоды, платежи, админ-операции) логируются.

## Миграции

Схема создаётся миграцией `migrations/versions/0001_initial.py`. Для PostgreSQL:

```bash
alembic upgrade head
```

Новая миграция после изменения моделей: `alembic revision --autogenerate -m "..."`, затем `alembic upgrade head`.
